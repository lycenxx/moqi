# 控制台：多模态对话、新样式、看过的动态

> 2026-11-23 定稿。实现以代码和测试为准。建立在 `2026-11-23-fewer-confirmations-design.md` 之上（确认框的第三个按钮、合并按钮的分支名）。

## 1. 目标

和用户确认过的选择：

- **多模态**：给 moqi 发图片（粘贴、拖入、选文件），moqi 看图回答；moqi 的回答有排版（Markdown），能显示它截的图和 MCP 工具返回的图。语音不做（macOS 自带听写在任何输入框里都能用）。
- **模型**：只用一个模型。控制台自动测出它能不能看图；看不了时图片按钮变灰，提示换一个能看图的模型（比如 `deepseek-flash`）。
- **样式**：效果图 A「留白 · 纸感」，用到所有页面。
- **动态**：处理过的卡片不消失，收进「看过的」，链接和改动以后还能点开。

## 2. 做法

图片存成文件：`<moqi 主目录>/media/<编号>.<扩展名>`，事件里只记编号。

没有选的做法：图片的 base64 写进事件日志（一张约 1 MB，日志膨胀，启动时整个读进内存）；图片只留在浏览器里（刷新就丢，后面几轮没法再交给模型）。

实现分四段，各自测试、各自提交：媒体和发图片、回答排版和工具图片、样式、看过的动态。

## 3. 发图片

### 3.1 媒体存储（`src/node/media.ts`）

- `mediaStore(home)`：
  - `save(bytes): string`：按文件头判断类型（PNG `89 50 4E 47`、JPEG `FF D8 FF`、GIF `47 49 46 38`、WebP `RIFF....WEBP`），别的类型、空文件、超过 3 MB 都抛错。编号 `m_` 加 16 位十六进制随机数。目录权限 `0700`，文件 `0600`。
  - `load(id): { type, data } | undefined`：`data` 是 base64。编号不合 `^m_[0-9a-f]{16}$` 时返回 `undefined`，不碰文件系统。
  - `read(id): { type, bytes } | undefined`：给控制台用。
- 内核不直接用它：`MoqiOptions.media?: { load(id): Promise<{ type: string; data: string } | undefined> }`，由家（`Home`）传进去。`src/core` 仍然不用 Node 接口。

### 3.2 控制台接口

- `POST /api/media`：请求体是图片本身（`Content-Type: image/*`），上限 3 MB（只对这个接口放宽，其他接口仍是 64 KB）。返回 `{ id }`；类型不对返回 415，太大返回 413。和其他接口一样要密钥。
- `GET /api/media?id=`：返回图片，`Content-Type` 按文件头，`Cache-Control: private, max-age=31536000, immutable`。编号不合格式返回 400，找不到返回 404。
- 页面用带密钥的 `fetch` 取图，转成 `blob:` 地址显示。内容安全策略的 `img-src` 加上 `blob:`，其他不变。

### 3.3 输入框

- 粘贴、拖入、点图片按钮选文件，三种方式都行。支持 PNG、JPEG、WebP、GIF，一条消息最多 4 张。
- 发送前在浏览器里处理：长边超过 2048 像素或文件超过 2 MB 的，用画布缩到长边 2048 并转成 JPEG（质量 0.85）；GIF 不转换，超过 2 MB 就提示太大。处理完立即上传，拿到编号。
- 输入框左侧显示缩略图，每张带移除按钮；上传中显示进度，失败的那张标红并说明原因。
- 只有图片、没有文字也能发。

### 3.4 对话

- `POST /api/chat { text, images?: string[] }`：`images` 最多 4 个，每个编号都要存在；文字和图片不能都为空。
- `moqi.chat(text, signal, { fromAgent?, images? })`。事件 `message` 加可选的 `images: string[]`。
- 模型契约：用户消息加可选的 `images: readonly { type: string; data: string }[]`。OpenAI 兼容适配器把它变成内容数组：`[{ type: "text", text }, { type: "image_url", image_url: { url: "data:<type>;base64,<data>" } }…]`；`noThink` 的开关加在文字部分后面。
- 历史：带进对话的历史里，最近 3 条带图的用户消息附上图片（通过 `media.load`）；更早的、或者图片读不到的，在文字后面加"[图片]"。
- 别的 agent 通过 `/api/chat` 的 `from`、MCP、A2A 发来的消息仍然只有文字。
- moqi 记忆和复盘（`learn`、`reflect`、`study`）只看文字，不分析图片。

### 3.5 能不能看图

- `POST /api/model/vision { model? }`：给模型发一张 32×32 的纯红 PNG（代码里的常量），问"这张图是什么颜色？只回答颜色。"（`maxTokens: 512`，`reasoning: "off"`；会先思考的模型要留出思考的 token，实测 `deepseek-flash` 在 20 的上限下回答是空的）。回答含"红"或"red"（不分大小写）算能看图。不带 `model` 时测当前模型，并把结果写进配置的 `model.vision`；带 `model` 时只返回结果。
- `POST /api/model/test` 同时测看图，返回里多一个 `vision`；设置页"测试连接"显示"能看图"或"看不了图"。
- 保存设置：表单里的接口地址和模型名正是刚测过的那一组时，把测出的 `vision` 一起写入；否则接口地址或模型名变了就去掉 `model.vision`，没变就保留原来的。
- `GET /api/state` 多一个 `vision: true | false | null`。
- 输入框：`vision` 为 `false` 时图片按钮变灰，悬停和点击都提示"当前模型看不了图，可以换成 deepseek-flash 这类能看图的模型"，粘贴和拖入的图片也不收。为 `null` 时，第一次添加图片先调用 `/api/model/vision`，显示"正在确认模型能不能看图…"，再按结果处理。

### 3.6 隐私

图片只存在本机，只发给用户配置的模型接口。删除对话历史的功能本次不做，图片随对话一直保留。

## 4. 回答的排版和图片

### 4.1 Markdown（`src/node/console/assets/markdown.js`）

- 新的静态文件，作为 `/markdown.js` 提供，在 `app.js` 之前加载。它在 `globalThis.moqiMarkdown` 上提供 `parse(text)`，返回纯数据的块和行内节点；`app.js` 用现有的 `h()` 把它们变成 DOM。全程不用 `innerHTML`。
- 块：段落、标题（`#` 到 `######`，显示为两级小标题）、有序和无序列表（可嵌套一层）、引用、代码块（带"复制"按钮）、表格（GitHub 的竖线写法）、分隔线。
- 行内：加粗、斜体、行内代码、链接 `[文字](地址)`、裸露的网址。
- 链接只认 `http:` 和 `https:`，新标签页打开，`rel="noopener noreferrer"`；别的协议原样显示成文字。
- 单独成段或单独成为列表项的链接显示成链接卡片：链接文字加域名。不加载网站图标和标题。
- 不渲染 HTML 标签（原样显示），不加载网上的图片（`![]()` 显示成链接）。
- 只用于 moqi 的回答。用户的消息原样显示。
- 系统提示里加一句：回答可以用 Markdown 的列表、加粗、代码、表格和链接。

### 4.2 工具返回的图片

- `ToolResult` 的对象形式加可选的 `images: readonly string[]`（媒体编号）。
- MCP 客户端：内容类型 `image`（带 `data` 和 `mimeType`）存进媒体，给模型的文字里写"[图片，已显示给用户]"。一次结果最多存 4 张。
- macOS 截图：截好以后把文件也存进媒体，结果带上编号。文件仍留在桌面。
- 一轮对话里所有工具结果的图片（最多 8 张）记在 moqi 那条回答的 `message.images` 里。
- 这些图片不交给模型看。

### 4.3 显示

- 用户发的图片在气泡上方，右对齐；moqi 的图片在回答下方。单张最宽 320px，多张排成网格。
- 点图片在页面里放大（`<dialog>`），Esc 或点背景关闭，焦点回到原图。图片的替代文字："你发的图片 1""moqi 带回的图片 1"。

## 5. 样式（A「留白 · 纸感」）

- 颜色（CSS 变量）：

  | 用途     | 浅色      | 深色      |
  | -------- | --------- | --------- |
  | 底色     | `#F8F8F6` | `#121414` |
  | 卡片     | `#FFFFFF` | `#1A1D1E` |
  | 正文     | `#1F2328` | `#E7E9EA` |
  | 次要文字 | `#5F6670` | `#9AA1A6` |
  | 分隔线   | `#E6E6E1` | `#2A2F31` |
  | 强调色   | `#2F6F67` | `#6FB8AD` |

  跟随系统切换。正文、次要文字和底色的对比度都不低于 4.5:1，实现时逐个核对。
- 字体：系统字体（`-apple-system`、`PingFang SC`、`Helvetica Neue`），不加载网络字体。正文 16px；对话行高 1.75；页面标题 28px。
- 对话：内容区最宽 720px；moqi 的回答不加气泡；用户的话用浅灰圆角气泡（`#ECECE8`，深色 `#24292B`）；输入框是浮在底部的胶囊（圆角 26px、浅阴影），左边缩略图，右边图片按钮和发送按钮。
- 空对话：按时间问候（早上好、中午好、下午好、晚上好），下面三条示例，点了填进输入框，不直接发：「把下载文件夹里的 PDF 收进一个新文件夹」「打开 news.ycombinator.com，挑 5 条翻成中文」「明天上午十点提醒我交周报」。没接模型时仍显示"先给 moqi 接一个模型"。
- 其他页面（待办、动态、记忆、设置）用同一套颜色、字号、卡片和按钮。顶部导航结构不变。
- 细节：图标都是线条风格的内联 SVG，不用 emoji；可点元素至少 44px，鼠标是手形，键盘焦点框清晰；过渡 150 到 200 毫秒，`prefers-reduced-motion` 时去掉；375、768、1440 三种宽度都不出现横向滚动。

## 6. 看过的动态

### 6.1 数据

- `OfferRecord` 加 `decidedAt`（`offer.feedback` 事件的时间）。
- `code.finished` 加 `head`（moqi 提交后的提交编号，没有改动时不带）；`code.merged` 加 `into`（合并进的分支）。`State.codeTasks` 记下这两项。

### 6.2 `GET /api/state` 的 `history`

- 包含：显示过（有 `surface`）、并且已经有回应或已经过期的提议；创建时间在 30 天内；按回应时间（没有时用过期时间）从新到旧，最多 100 条。
- 每条：`id`、`kind`、`title`、`body`、`links`、`at`、`decidedAt`、`outcome`、`taskId`（编程任务）。
- `outcome` 的文字：
  - 接受：一般为"好"；编程任务为"已合并到 <into>"。
  - 拒绝：一般为"你说不用"；编程任务被丢弃为"已丢弃"。
  - 没理：`你没理`；关掉这类：`你关掉了这类`；过期没回应：`没理会，过期了`。
- 编程任务另带 `stat` 和 `canDiff`（已合并且记了 `head`）。
- `GET /api/code/diff?id=`：已合并的任务改用 `git diff <base>..<head>`；丢弃的任务返回 409 "这个任务丢弃了，改动没有留下"。

### 6.3 页面

- 顺序：正在跑的编程任务 → 待处理的卡片 → 「看过的」（标题旁写"最近 30 天 · N 条"）→ 「moqi 在想」。
- 「看过的」先显示 10 条，下面"再看 20 条"。卡片用虚线边框，保留标题、正文和链接（链接卡片可点）；按钮换成一行结果和时间，接受的前面带一个对勾图标。可以看改动的编程任务保留「看改动」。
- 「moqi 在想」：`/api/state` 的想法里加 `offerId`。对应的卡片在待处理或「看过的」里时，标题是按钮：点了滚到那张卡片（需要时先展开"再看"），高亮 2 秒。找不到卡片时标题只是文字。

## 7. 测试

- `test/media.test.ts`：四种格式的识别；拒绝别的类型、空文件、超过 3 MB；编号格式不对时不读文件；权限 `0700` 和 `0600`。
- `test/agent.test.ts`：带图的消息交给模型的格式；最近 3 条带图的消息带图，更早的变成"[图片]"；读不到的图变成"[图片]"；工具结果的图片记进回答，不交给模型。
- `test/agent.test.ts`（模型适配器的测试也在这里）：内容数组的格式，`noThink` 加在文字部分。
- `test/markdown.test.ts`：每种块和行内写法；HTML 原样显示；`javascript:` 和 `data:` 链接不变成链接；链接卡片的判定；表格。
- `test/console.test.ts`：`/api/media` 的上传、类型、大小、编号格式、密钥；`/api/chat` 带图；`/api/model/vision` 的判定（替身模型答"红色"和"我看不到图片"）和写配置；换模型后 `vision` 被去掉；`history` 的内容、`outcome`、30 天和 100 条上限；已合并任务的改动；内容安全策略含 `blob:`。
- `test/interop.test.ts`：MCP 返回图片时存进媒体，回答带上编号。
- `test/mac.test.ts`：截图结果带编号。
- 截图检查：对话（有图、有排版）、动态（含看过的）、设置，浅色和深色，375、768、1440 三种宽度。
- 真机：在控制台粘贴一张截图问问题（换成能看图的模型），确认 moqi 能读出图里的字；看不了图的模型按钮变灰。
- 完成标准：`pnpm check` 全部通过。

- 图片以外的附件（PDF、文档）。
- 删除对话和图片。
