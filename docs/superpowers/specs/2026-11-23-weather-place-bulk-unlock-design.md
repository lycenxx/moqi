# 天气地点、整组放开、「现在想一想」挪到顶部

> 2026-11-23 定稿。实现以代码和测试为准。

## 1. 起因

- 用户住南京，配置里的天气却是模板自带的北京；天气工具只能查配置的地点；记忆里的城市和配置没人核对。结果是标题写着"南京天气"的盯梢报的是北京。
- MCP 服务器的写工具要一个个放开，Playwright 一个服务器就有二十多个。
- 「现在想一想」在动态页底部，用户想放到最顶端。

## 2. 天气

### 2.1 模板

`TEMPLATE` 去掉 `weather`。天气地点只由用户在设置里搜城市，或者接受下面 2.3 的提议来设。

### 2.2 工具可以按城市查

- `weather` 的输入：`{ day: "today" | "tomorrow", place?: string }`。
- 带 `place`：用 Open-Meteo 地理编码（`count=1&language=zh`）找到坐标，按名字缓存在进程里；找不到就报错"找不到「X」这个地方"。回答里用查到的地名。
- 不带 `place`：用设置里的地点；没设就报错"还没设天气地点：告诉我城市，或者在设置里搜一下"。
- 插件总是加载，没设地点时也有工具；简报里的天气和晚上的带伞提醒，只在设了地点时才有。
- 工具描述写明：问设置地点以外的城市、或者还没设地点时，填 `place`。盯梢照常把参数存下来，所以"南京天气"的盯梢会带着 `place: "南京"`。

### 2.3 记住的城市和天气地点对不上，问一次

- 插件的 `tick` 里，从用户自己说的、没淡出的事实（不含别的 agent 写的）里找"住在 X""家在 X"，取第一个。X 的取法：关键词后面连续的汉字，到标点为止，最多 8 个；遇到"市、省、区、县"就截在它前面；还长于 3 个字时取前 2 个（"深圳南山"取"深圳"）。
- 事实里提到了设置的地点（去掉"市"）就算一致。否则，如果还没为同一个 X 提过 `weather.place`，就提一次：
  - 标题 `天气要改成南京吗？`；正文 `你说过住在南京，天气现在设的是北京。`（没设地点时：`你说过住在南京，天气还没设地点。`）
  - `value: 0.6`、`urgency: "whenever"`，动作 `weather_use_place { place: "南京" }`。
- `weather_use_place`：隐藏工具，`effect: "write"`，只能由接受提议触发（接受时算已同意）。它先地理编码，再通过 Home 注入的 `save(location)` 写进配置，然后 moqi 按新配置重建。返回 `好，天气改成南京了`。

## 3. 整组放开

- `Moqi.setSourcePolicy(source, policy: "ask" | "auto")`：把这个来源下的危险工具（不含隐藏的）都设成这个策略，返回 `把 browser 的 21 个工具都放开了；这一轮读过外部内容时仍会先问` 或 `browser 的 21 个工具以后每次都先问`。这个来源下没有危险工具就报错。
- `POST /api/tool-policy/source { source, policy }`。
- 设置页「会改动东西的工具」按来源分组。有两个以上工具的组，标题行带两个按钮：「全部放开」（点一下变成「确定全部放开」，再点才生效）和「全部每次都问」。单个工具的下拉框保留。
- 只改现在的工具；这个来源以后多出来的工具仍从"每次都问"开始。

## 4. 「现在想一想」挪到顶部

动态页标题「动态」那一行右边放「现在想一想」；「moqi 在想」那一节只留状态和列表。

## 5. 测试

- `test/plugins.test.ts`：带 `place` 时先地理编码、用查到的地名，同一个名字只编码一次，找不到时报错；没设地点不带 `place` 时报错；对不上时提一次、动作是 `weather_use_place`，一致时不提，同一个城市不重复提；接受后调用 `save`；简报和带伞提醒在没设地点时不出。
- `test/node.test.ts`：模板里没有 `weather`。
- `test/autonomy.test.ts` 或 `test/safety.test.ts`：`setSourcePolicy` 只动这个来源的危险工具，不碰隐藏工具，没有工具时报错。
- `test/console.test.ts`：`/api/tool-policy/source` 的成功和 400；`/api/state` 照旧。
- 截图：设置页分组和两步确认，动态页顶部的按钮。
- 完成标准：`pnpm check` 全部通过。
